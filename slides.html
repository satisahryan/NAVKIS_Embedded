What is an embedded system?

A computer dedicated to one job, built into a larger product, that senses the world and acts on it — usually under limits of cost, power and time.

…and the loop runs forever: while(1) { sense(); compute(); act(); }

The Arduino “superloop”

// what you write
void setup() {   // once, at power-on
  pinMode(26, OUTPUT);
}
void loop() {    // forever
  digitalWrite(26, HIGH);
  delay(500);
  digitalWrite(26, LOW);
  delay(500);
}
// what the framework hides
int main() {
  initHardware();   // clocks, flash, RAM
  setup();
  while (true) {
    loop();
  }
}
// On the ESP32, loop() actually runs
// inside a FreeRTOS task (more later).

There is no “exit”. Firmware never ends — it only resets.

02

Talking to pins

GPIO · interrupts · analog

GPIO: a pin you control from code

  • Output: digitalWrite(26, HIGH) → pin at 3.3 V
  • Input: digitalRead(4) → is the voltage high or low?
  • Under the hood, it is one register write:
// friendly
digitalWrite(26, HIGH);
// what it boils down to on the ESP32
GPIO.out_w1ts = (1 << 26); // "write 1 to set"

Deep dive “w1ts” registers set bits atomically, so you never need a read-modify-write.

The problem with delay()

While delay(500) runs, the CPU does nothing: no button checks, no sensor reads, no Wi-Fi.

Two LEDs at different rates? Impossible to do cleanly with delays.

Fix: don’t wait — check the clock.

unsigned long last = 0;

void loop() {
  if (millis() - last >= 500) {
    last = millis();
    toggleLed();
  }
  // free to do other work here!
  checkButton();
  readSensor();
}

Inputs: pull-ups and floating pins

  • An unconnected input floats: it picks up noise and reads random 0s and 1s.
  • A pull-up resistor gently holds it HIGH.
  • The button connects the pin to GND → reads LOW when pressed.
  • The ESP32 has internal pull-ups: pinMode(4, INPUT_PULLUP)

Polling vs. interrupts

📱 PollingChecking your phone every few seconds for a message.

if (digitalRead(4) == LOW) …

Simple, but it wastes time and misses short events while the CPU is busy.
🔔 InterruptThe phone rings. You stop, answer, then carry on.

attachInterrupt(…, onButton, FALLING)

The hardware calls your ISR the moment the edge arrives.
ISR rules: keep it tiny · no delay()/Serial · share data via volatile flags · IRAM_ATTR keeps it in fast RAM

Switch bounce

One press ≠ one edge. Metal contacts chatter for a few milliseconds.

The analog world → numbers: the ADC

  • Nature is analog: temperature, light, sound all give voltages.
  • The ADC samples a voltage and returns a number.
  • ESP32: 12-bit → 212 = 4096 levels, 0–4095
  • Resolution: 3.3 V / 4096 ≈ 0.8 mV per step
  • Deep dive The ESP32 ADC is not perfectly linear near 0 V and 3.3 V. Real products calibrate it, or use an external ADC.

Numbers → the analog world: PWM

  • The pin can only be fully ON or OFF…
  • …but switch it fast enough and the LED, motor or eye sees the average.
  • Duty cycle = ON time / period
  • analogWrite(26, 64) → 64/255 ≈ 25 % → about 0.83 V average
  • Used for LED dimming, motor speed, servo position, even audio

From device to cloud

MQTT: publish / subscribe

  • Devices never talk directly. They talk to a broker.
  • Publish a message to a topic: navkis/ews2026/ravi/data
  • Subscribe to topics, with wildcards: navkis/ews2026/+/data
  • Tiny headers and one long-lived TCP connection → ideal for small, battery-powered devices
  • Compare with HTTP: the device would have to keep asking “any commands for me?”

When the superloop is not enough: RTOS

  • A task is like a thread with its own stack and a priority
  • The scheduler runs the highest-priority ready task, preemptively
  • vTaskDelay() blocks only this task — the others keep running
  • Queues and semaphores pass data and protect shared resources
  • The ESP32 runs FreeRTOS on 2 cores. Wi-Fi already lives in its own tasks!
